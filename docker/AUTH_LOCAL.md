# Локальная проверка регистрации и сессии

Это отдельное окружение без копии production-БД. Существующие контейнеры и
том `themesphone-local_postgres_data` не используются. В новой БД изначально нет
обоев и администраторов. PostgreSQL, Strapi и почта доступны только на loopback.

## Windows — Local Terminal Termius, PowerShell

Из корня проекта, с установленными зависимостями backend/frontend и Node.js 22:

```powershell
node scripts/local-auth.cjs setup
docker compose --env-file .local/auth/backend.env -f compose.auth.yaml config --quiet
docker compose --env-file .local/auth/backend.env -f compose.auth.yaml up -d --wait
```

Проверив успешный запуск, в отдельном локальном терминале:

```powershell
node scripts/local-auth.cjs start
```

Скрипт генерирует отдельные секреты в игнорируемом `.local/auth/backend.env`,
не читает `backend/.env`, отказывается запускаться с другой БД и не заменяет
существующий env-файл. Локальный Strapi: `http://127.0.0.1:1339`.
Включает подтверждение email и только email-вход; OAuth проверяется отдельно.
Публичные права ограничены чтением каталога, authenticated дополнительно получает
доступ к своему `/users/me`. Шаблон и настройки писем задаются в локальной БД.
Автогенерация документации в этом окружении отключена.

Письма перехватывает Mailpit: `http://127.0.0.1:8026` (SMTP 1026).
На настоящие почтовые адреса они не доставляются, SMTP-пароль не нужен.
Образ Mailpit закреплён digest. Не публикуйте Mailpit в интернет.

### Яндекс SMTP вместо Mailpit

Отдельный игнорируемый файл `.local/smtp/backend.env` хранит только SMTP-настройки.
Пароль приложения вводится пользователем в `SMTP_PASS="..."` через локальный
редактор. Не передавайте пароль в аргументах команд, чате, скриншотах или логах.

После сохранения файла и остановки локального Strapi:

```powershell
node scripts/local-auth.cjs start --smtp-yandex
```

Отдельная проверка TLS и авторизации, без отправки письма и без перезапуска Strapi:

```powershell
node scripts/check-yandex-smtp.cjs
```

Скрипт не выводит пароль, SMTP-ответ или объект ошибки; при неудаче выводит
только код ошибки и числовой SMTP-статус. Успех не подтверждает доставку писем:
её проверяют отдельно на согласованном адресе получателя.

Чтобы при запуске отправить ровно одно тестовое письмо согласованному получателю,
добавьте `--send-test=адрес`. Повторных попыток автоматически нет. Результат приёма
SMTP сохраняется в `.local/smtp/test-email-result.json` без паролей и токенов.
Это подтверждает приём Яндексом, но попадание во «Входящие» проверяет получатель.
Автоматические сценарии регистрации/восстановления откажутся работать, если
`.local/auth/runtime.json` указывает реальный SMTP; для них перезапустите с Mailpit.

Этот явный флаг подключает `smtp.yandex.ru:465` с TLS и ящик
`noreply.themesphone@yandex.ru`. Отправитель шаблонов в локальной БД меняется на
тот же адрес. Остальные настройки, отдельная БД и loopback-привязка сохраняются.
Без флага используется Mailpit. Пустой пароль останавливает запуск до подключения
к БД. Не запускайте массовые автоматические проверки с реальным SMTP: для них
нужен обычный режим Mailpit. Тестовые ссылки ведут на этот же компьютер,
`http://127.0.0.1:3100`, и не являются production-ссылками.

Frontend запускается с адресами **этого** Strapi. Сначала остановите текущий frontend:

```powershell
$env:NEXT_PUBLIC_STRAPI_URL='http://127.0.0.1:1339'
$env:STRAPI_API_URL='http://127.0.0.1:1339'
$env:FRONTEND_URL='http://127.0.0.1:3100'
Set-Location frontend
npm run build
npm run start -- --hostname 127.0.0.1 --port 3100
```

Публичный адрес CMS встроен в сборку: перед возвратом к другому окружению нужна
пересборка с его `NEXT_PUBLIC_STRAPI_URL`. Пользуйтесь одним адресом
`http://127.0.0.1:3100`, чтобы origin и cookie не различались из-за localhost.

## Проверки

Из корня, при запущенном локальном Strapi и Mailpit:

```powershell
node --experimental-strip-types scripts/check-local-auth.mjs
node --experimental-strip-types scripts/check-local-auth.mjs --http
node --experimental-strip-types scripts/check-account-recovery.mjs --http
node scripts/check-local-oauth.cjs
node scripts/check-account-merge.cjs
node --experimental-strip-types --test frontend/tests/*.test.mjs
```

Интеграционная проверка создаёт одноразовую учётную запись `@example.test`.
Вариант `--http` проверяет реальные HTTP-маршруты запущенного frontend на порту 3100.
Проверяет одно письмо, запрет входа до подтверждения, одноразовую ссылку,
неверный пароль, HttpOnly-cookie, чтение своей сессии, выход и отказ чужому Origin.
Пароли, JWT и ссылки подтверждения в результат не выводятся.

В браузере: регистрация → письмо Mailpit → подтверждение → вход → кабинет → выход.
Подтверждение не создаёт сессию автоматически: после него нужно войти с паролем.
HttpOnly-cookie недоступна JavaScript; `/api/me` использует её на сервере.
Для локального HTTP Secure не устанавливается; в production HTTPS — устанавливается.

Восстановление доступно на `/auth/forgot-password`. Ссылка одноразовая, действует
один час; одновременные запросы синхронизируются блокировкой строки PostgreSQL.
Повторный запрос письма заменяет предыдущую ссылку. Смена пароля из кабинета
также отменяет отправленные ранее ссылки. Ответ запроса письма одинаков для
существующего и неизвестного email. После восстановления требуется обычный вход.
Текущая JWT-модель Strapi не отзывает автоматически сессии на других устройствах.

В профиле сохраняются имя, фамилия, телефон и адрес выставления счёта.
Email доступен только для чтения: его смена требует отдельного подтверждения.
Маршрут `/api/account/profile` выбирает владельца из сессии Strapi, а не из тела.
Проверка восстановления использует только локальную БД для имитации просроченной
ссылки, проверяет двух пользователей, подмену полей, конкурентный сброс и оба
способа смены пароля. Пароли и токены в вывод не попадают.

OAuth и объединение профилей проверяются при запуске Strapi с `--oauth`:
см. `../backend/OAUTH_SETTINGS.md`. Проверка объединения использует локальную
PostgreSQL, подставные сервисы и Mailpit, отказывается работать с production
и удаляет созданные ею записи. Реальный вход через сервисы проверяется отдельно
на HTTPS; локальные тесты не доказывают корректность внешних OAuth-настроек.
Подписка на рассылку остаётся отдельной задачей. Production SMTP и шаблоны
настраиваются по `../backend/AUTH_SETTINGS.md` отдельно от локального окружения.
Ограничения публичного Caddy этим изменением не снимаются. Перед публикацией
потребуются отдельная проверка настроек production Strapi и разрешений маршрутов.
Настройки и изменения схемы описаны в `../backend/AUTH_SETTINGS.md`.

## Остановка

Strapi/frontend: Ctrl+C в их терминалах. Из корня:

```powershell
docker compose --env-file .local/auth/backend.env -f compose.auth.yaml down
```

Без `-v`: тестовая БД сохраняется. Не выводите resolved Compose config без `--quiet`.
