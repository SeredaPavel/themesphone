# Один оригинал на товар

## Выбранная архитектура: Yandex Object Storage

14.11.2026 пользователь выбрал S3 в Yandex Cloud. Два отдельных бакета:
**закрытые оригиналы** и **публичные превью**. Постоянное хранение новых файлов
и трафик скачивания вынесены с VPS. Описанный ниже локальный файловый драйвер
сохранён для изолированных проверок, но больше не является планом production.

Подготовлены S3 SDK, upload-provider Strapi 5.14.0, генерация публичного превью,
закрытая запись оригинала и выдача короткой подписанной ссылки после проверки
товара. Пользователь создал `themesphone-originals` и `themesphone-previews`,
сохранил ключ вне Git. После исправления ACL 14.11.2026 реальные проверки
`check-object-storage.cjs` и `--write-test` прошли: доступ к обоим бакетам,
закрытый оригинал, подпись/attachment/точные байты и публичное превью.
Все объекты, созданные облачным тестом, успешно удалены. Проверка выполнена
из локального окружения; production пока не активирован.
В админке добавлен раздел **«Оригиналы обоев»** в общем стиле сайта. Импортёр
также сохранён. Обычная медиатека Strapi сохраняет файлы **публично**:
настоящие оригиналы через неё не загружать.

### Работа в админке

1. В Content Manager создать товар, указать `isFree` явно, цену, категорию и
   устройство, затем сохранить. Публиковать заранее не требуется.
2. Открыть **«Оригиналы обоев»**, найти товар по названию, нажать «Выбрать».
3. Выбрать один исходный JPEG/PNG/WebP до 50 МиБ и 40 миллионов пикселей и нажать
   **«Загрузить оригинал»**. Дождаться сообщения об успехе и размеров файла.
4. В Content Manager проверить превью и описание, затем опубликовать товар.
   Загрузка сама не публикует черновик и не меняет цену/описание. Для уже
   опубликованного товара бесплатность черновика и публикации должна совпадать:
   несовпадение блокирует импорт, чтобы прежняя бесплатная версия не открыла
   новый платный оригинал.

Доступ имеет Super Admin; другим административным ролям нужно выдать отдельное
разрешение «Загружать оригиналы обоев». Обычные пользователи сайта и их JWT
доступа не получают. В списке есть поиск и постраничный вывод. Готовый оригинал
не перезаписывается. Для другого файла нужен другой товар, версии добавим позже.
Публичный Content API товаров принудительно использует опубликованный статус;
запросы `status=draft` отклоняются, в том числе от пользователей сайта.
Одновременно backend обрабатывает один оригинал; временные multipart-файлы
удаляются также при ошибках. Реальный интеграционный тест раздела:
`node --experimental-strip-types scripts/check-originals-admin.cjs` (только
изолированная БД + Mailpit + собственные S3-fixtures; удаляет их после проверки).

### Подключение облака

1. Создать два бакета стандартного класса. У оригиналов отключить все варианты
   публичного доступа. У превью разрешить только чтение объектов, оставив
   просмотр списка и чтение настроек закрытыми. Имена должны быть различными,
   из строчных латинских букв, цифр и дефиса, без точек.
2. Создать отдельный сервисный аккаунт `themesphone-storage`. Дать ему READ и
   WRITE через ACL **этих двух бакетов**, без прав администратора облака.
   Создать для него статический ключ доступа S3. Не путать его с OAuth,
   IAM-токеном или авторизованным SSH-ключом.
3. Локальные значения вне Git: `.local/storage/backend.env`; шаблон переменных
   находится в `backend/storage.env.example`. Секреты не выводить в терминал
   и не отправлять в чат. Файл не загружается автоматически текущим preview:
   незавершённая настройка облака не ломает локальный каталог.
4. Выполнить проверки ниже. Для настоящих оригиналов определить независимое
   резервное копирование и версионирование. S3 и версионирование сами по себе
   не заменяют отдельную резервную копию.

Windows — Local Terminal Termius, PowerShell, из корня проекта:

```powershell
node backend/scripts/check-object-storage.cjs
node backend/scripts/check-object-storage.cjs --write-test
```

Первая команда проверяет доступ к бакетам без записи. Вторая создаёт собственные
маленькие тестовые JPEG: проверяет отказ анонимному читателю оригинала,
доступ через подпись, attachment, точные байты и публичное превью, затем удаляет
только созданные ею объекты и их версии. Не меняет ACL, настройки бакетов или БД.
Ключи и подписанные URL не выводятся. Если процесс был принудительно прерван,
возможные тестовые объекты нужно сверить отдельно, не очищая бакеты целиком.

Для импорта в изолированную локальную БД добавить `--s3`:

```powershell
node backend/scripts/import-original.cjs --local --s3 --wallpaper DOCUMENT_ID --file 'C:\путь\оригинал.jpg'
node backend/scripts/import-original.cjs --local --s3 --wallpaper DOCUMENT_ID --file 'C:\путь\оригинал.jpg' --apply
```

Использовать новый тестовый товар: существующий оригинал неизменяем и повторно
не импортируется. Импортёр временно обрабатывает изображение на машине запуска.
Исходник отправляется отдельным PutObject в закрытый бакет; только уменьшенный
JPEG передаётся публичному upload-provider. Размер, MIME, SHA-256, ETag и версия
объекта проверяются перед регистрацией. Доступность оригинала без подписи
прерывает импорт. При ошибке БД удаляются только новые объект/превью.

### Выдача S3

Сервис сначала проверяет опубликованный товар и `isFree === true`, затем
HeadObject сверяет сохранённые метаданные/ETag. Только после этого подписывает
GET на конкретный ключ и, если есть, версию объекта. TTL по умолчанию 120 секунд
(разрешены 30–300). Ссылка временная, **не одноразовая**. HEAD проверяет наличие
и метаданные, но не создаёт GET-ссылку. Платные оригиналы до этапа заказов/оплаты
всегда отклоняются; старое `paid:true` и клиентская цена прав доступа не дают.

Next.js принимает только редирект своего Strapi на точный закрытый бакет и
префикс `originals/` в `https://storage.yandexcloud.net`. Ответ `302` автоматически
передаёт браузер в Object Storage, где `Content-Disposition: attachment`
запускает обычное скачивание. Файл не буферизуется и не передаётся через VPS.
Ответы содержат `no-store` и `no-referrer`. Подписи не включаются в каталог.
Сайт принимает изображения только из своего публичного бакета `previews/`.

### Включение на production — отдельный следующий этап

- Прочитать актуальную конфигурацию, сохранить БД и настройки ThemesPhone.
- Передать backend переменные из шаблона; frontend — **только**
  `S3_ORIGINALS_BUCKET` и `S3_PREVIEWS_BUCKET` (имена, без ключей).
  Backend env_file и frontend env_file уже предусмотрены Compose.
- Проверить безопасную загрузку через раздел «Оригиналы обоев». Не включать
  публичную загрузку оригиналов через стандартную медиатеку.
- Выпустить проверенный код и адресно открыть GET/HEAD `/api/download` на сайте.
  CMS-маршрут скачивания оставить закрытым снаружи; сервер Next обращается
  к нему во внутренней сети. Остальные API и соседние проекты не затрагивать.
- Проверить бесплатное скачивание, платный отказ и превью на обоих доменах.
- Дополнить порядок восстановления: БД, соответствующие версии объектов,
  публичные превью и локальные старые uploads. Существующий deploy-снимок
  **не копирует S3**, это отдельная задача резервирования.

Папку originals на VPS и её bind mount для S3 создавать не требуется.
Тестовые старые изображения не мигрируют автоматически и пока остаются публичны.

## Локальный файловый драйвер (для проверок)

## Текущее состояние

Локально реализованы импорт оригинала, создание публичного превью и безопасная
бесплатная выдача. Платные оригиналы выдачей всегда отклоняются до готовности
заказов и подтверждённой оплаты. Работа ведётся в `devcodex`; файловая папка
используется только локальными проверками. Production подключается по S3-схеме
выше; обычный push кода не заменяет настройку облака и публичного маршрута.

Нынешние изображения сайта пользователь подтвердил как тестовые: они будут
заменены. Их не переносим как реальные коммерческие оригиналы. Старые URL этих
тестовых картинок остаются публичными до замены контента.

## Хранение и доступ

- `WALLPAPER_ORIGINALS_DIR` — абсолютный путь к папке **вне `public`**.
  Без него выдача закрыта. Оригиналы не входят в Git или Docker-образ.
- Закрытая коллекция `wallpaper_files` хранит связь с `documentId` товара,
  случайный ключ файла, SHA-256, MIME, размеры и количество байтов. CRUD API и
  раздел Content Manager для неё не созданы; ключ и checksum также private.
- Один товар — один неизменяемый оригинал. Повторный импорт отклоняется;
  случайная замена уже купленного файла недопустима. Версии добавим отдельно.
- Импорт определяет настоящий формат через Sharp: JPEG, PNG или WebP,
  один кадр, до 50 МиБ и до 40 миллионов пикселей. Оригинальные байты сохраняются.
- Только производное JPEG-превью, максимум 512×1024, передаётся upload-сервису
  Strapi. Обновляются ссылки `image` на draft/published строках без публикации
  остальных черновых правок. Старые медиафайлы автоматически не удаляются.
  Исходник внутри `public` импортёр отклоняет: копирование такого файла в
  закрытую папку само по себе не убирает его прежнюю публичную копию.
- Каталог получает только `originalFile: { id, mime, bytes, width, height }`.
  Путь, имя в хранилище и SHA-256 не передаются посетителю.
- `/api/wallpaper-files/:fileId/download` проверяет актуальный опубликованный
  товар. Только `isFree === true` даёт доступ без регистрации; false/null/строка,
  снятие с публикации, отсутствующий файл или изменённый размер не дают файл.
  Клиентские цена, пользователь и старое `paid: true` не учитываются.
- Next.js `/api/download?file=ID` обращается только к своему настроенному Strapi,
  без редиректов, произвольных URL и полного буферирования. Проверяет MIME,
  размер/длину потока, attachment и поддерживает HEAD. Ответ: attachment с UTF-8
  именем, `private, no-store`, `nosniff`; оборванный или лишний поток отклоняется.
- При ошибке браузер получает страницу `/download/error` в общем стеклянном
  стиле, с безопасным возвратом к товару и фильтрам. API получает код ошибки.

## Импорт

Сначала создать товар, явно указать бесплатность и опубликовать. Для **реальных
новых оригиналов** не использовать обычную загрузку в медиатеку: она публична.
Указать оригинальный локальный файл командой ниже — превью создастся само.

Windows — Local Terminal Termius, PowerShell, из `backend`:

```powershell
$env:WALLPAPER_ORIGINALS_DIR='C:\Users\filkm\Projects\wallpaper_shop\.local\originals'
npm run original:import -- --local --wallpaper DOCUMENT_ID --file 'C:\путь\к\оригиналу.jpg'
```

Команда без `--apply` читает конфигурацию и товар, проверяет файл и показывает
план импорта. Запуск Strapi синхронизирует схему обычным способом: перед первым
запуском новой версии нужна копия БД. Содержимое env и секреты не выводить.
`--local` выбирает только `.local/auth/backend.env`, проверяет имя/адрес тестовой
БД и отключает внешнюю почту. Без него требуется явно переданное production-
окружение; случайный запуск с `backend/.env` не допускается.
Папка хранилища должна существовать заранее. Если план верен:

```powershell
npm run original:import -- --local --wallpaper DOCUMENT_ID --file 'C:\путь\к\оригиналу.jpg' --apply
```

На VPS импорт требует отдельного согласованного этапа установки. Это запуск
Strapi с БД и запись файлов; не запускать второй экземпляр рядом с работающим
backend на малом VPS. Подготовить окно обслуживания только ThemesPhone.
Интерфейс загрузки оригинала в админке можно добавить поверх этого же сервиса.

## Локальная проверка

Windows — Local Terminal Termius, PowerShell, из корня проекта:

```powershell
node --experimental-strip-types scripts/check-local-downloads.cjs
```

Только `themesphone_auth_dev`, PostgreSQL loopback:5434 и Mailpit. Скрипт сохраняет
custom-format dump и проверяет его TOC, запускает временный Strapi на 1341,
создаёт собственные fixtures и удаляет их в finally. Проверяет настоящие HTTP-
ответы Strapi и функцию Next BFF: точные байты/SHA-256, HEAD, метаданные, уменьшенное
превью, запрет прямых путей, платного/неопубликованного файла, неопределённой
бесплатности, изменённого размера и старого URL-прокси. Также проверяется откат
обеих версий товара, metadata и файлов при сбое на втором обновлении image.
Учётки не создаёт.
Резервная копия сохраняется в `.local/backups/download-stage`.

Откат образов не откатывает импортированные данные. Для выпуска следовать
S3-подготовке в начале документа; затем переходить к корзине/заказам и оплате.
