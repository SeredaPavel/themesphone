# История покупок и повторные скачивания

Подготовлено 16.11.2026. История в кабинете обращается к Next GET
`/api/account/orders?page=N`; BFF передаёт только HttpOnly JWT пользователя.
На стороне Strapi каждый заказ выбирается с фильтром владельца. По 20 заказов
на страницу, без произвольного populate/owner/query. История остаётся видимой
после окончания срока скачивания.

Кнопка «Скачать оригинал» находится на странице заказа и в его строке в кабинете.
Она обращается к `/api/download?file=FILE_ID&order=ORDER_UUID`. BFF проверяет формат
и передаёт JWT и reference только фиксированному внутреннему Strapi. Обработчик
повторно проверяет живой аккаунт, принадлежность заказа и наличие именно этого
file ID в сохранённом составе. Клиент не управляет владельцем, ценой или сроком.

Состояние заказа само по себе недостаточно: требуется сохранённая попытка
платежа succeeded с соответствующим режимом, providerId, metadata и суммой.
Старые `orders.paid=true` никаких прав не дают. Переходы браузера и JSON webhook
тоже не являются доказательством оплаты.

## Корзина и повторная покупка

Корзина сверяет выбранные documentId через GET `/api/account/orders?items=ID,ID&checkoutKey=UUID`.
Это отдельный строгий режим того же BFF: до 30 уникальных ID, без page/owner/populate.
Внутренний GET /api/shop-orders применяет фильтр текущего владельца и ищет покупки
в сохранённом JSON-составе, включая записи за пределами первой страницы истории.
Проверяются подтверждённая попытка и режим платежа; чужие покупки и просто paid-флаги
не учитываются. После перехода к live тестовые покупки не будут исключать настоящие
товары из оплаты.

Оплаченный товар, добавленный повторно, остаётся в корзине с отметкой
«Вы уже оплатили этот товар», скачиванием и нулевым вкладом в сумму нового заказа.
Истечение срока загрузки не является разрешением повторно списать деньги: такой
товар также исключается из суммы, а интерфейс показывает окончание срока.
Сервер повторяет проверку при создании заказа и перед началом платежа. Смешанный
заказ содержит только новые позиции; если оплачено всё, новый заказ не создаётся.

Обработанные заказы помечаются в локальном хранилище, незавершённые привязаны к
пользователю и сохраняются до возврата. Подтверждение очищает только позиции этого
заказа, сохраняя добавленное позднее. Вкладки синхронизируются через storage,
а возврат/фокус и восстановление страницы из browser cache запускают сверку.
Старый оплаченный заказ нельзя повторным просмотром использовать для удаления
только что добавленного товара. При сбое проверки покупок оформление блокируется
до повторной проверки. После оплаты показаны скачивания и «Мои покупки»;
кнопки возврата в корзину на завершённом заказе нет.

## Срок

`ORDER_DOWNLOAD_DAYS=0` — без ограничения. `1..3650` — число суток после оплаты.
Это значение сохраняется в момент создания заказа; изменение env касается
только будущих покупок. Начало отсчёта — сохранённый paidAt (captured_at от
провайдера; если отсутствует — время первого подтверждения сервером).
Для старых записей без paidAt используется время сохранённой проверки платежа.

Срок права покупки и срок подписанной ссылки — разные вещи. Ссылка S3 действует
обычно 120 секунд. При каждом новом нажатии сервер проверяет право заново и
формирует свежую ссылку, если срок покупки не истёк. Оригинал не копируется на VPS.

Доступ сохраняется при объединении профилей и снятии товара с публикации:
используются владелец заказа и неизменяемый ID оригинала, название взято из
снимка заказа. Удаление самого файла/объекта администратором делает его недоступным.

## Тестовые платежи

Обычные оригиналы недоступны после тестовой оплаты. Для полного тестового пути
при загрузке через раздел «Оригиналы обоев» есть выключенный по умолчанию
флажок «Тестовый файл». Он сохраняется как приватное свойство оригинала,
доступное только администратору. test_paid + succeeded в тестовом магазине
открывает только такой тестовый оригинал. Для остальных файлов показывается
пояснение; настройки нельзя передать через корзину или клиентский заказ.

Боевые ключи и live-платежи всё ещё запрещены текущим платёжным адаптером.
Переход к настоящим продажам потребует оформления продавца, проверки чеков и
возвратов, независимой копии S3 и отдельного включения реального платёжного режима.

## Проверки

Тесты `order-downloads.test.cjs`, frontend checkout/download tests и интеграция
`scripts/check-local-orders.cjs` проверяют:

- чужого/анонимного/архивного пользователя, поддельный reference и metadata;
- запрет обычного оригинала после test_paid;
- несколько скачиваний с точным совпадением байтов;
- скачивание после unpublish и переноса заказа при объединении профилей;
- точную границу окончания срока и сохранение истории;
- HttpOnly JWT в запросе только к внутреннему CMS и безопасные ссылки в UI.

Внешний CMS API оригиналов и заказов остаётся закрыт в Caddy. Разрешён только
соответствующий Next BFF. Правила соседних сайтов на VPS не меняются.
