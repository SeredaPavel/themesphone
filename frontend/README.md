# ThemesPhone frontend

Next.js 15.5.28, TypeScript и Node.js 22. Версии зависимостей закреплены в package-lock.json.

## Ветки и проверки

- `devcodex` — текущая разработка.
- `dev` — проверка подготовленных изменений.
- `main` — production: push запускает сборку и развёртывание на VPS.

Слияния, коммиты и отправка изменений выполняются после подтверждения владельца.
GitHub Actions проверяет все три ветки и PR: TypeScript, тесты контракта каталога,
сборку Docker-образов, запуск с временной БД и скрипты развёртывания.
PR не публикует образы и не выполняет deploy. Публикация кода приложения
не переносит настройки из локальной админки Strapi в production.

## Windows — Local Terminal Termius, PowerShell

Требуется Node.js 22 с npm. Из корня проекта:

```powershell
Set-Location C:\Users\filkm\Projects\wallpaper_shop\frontend
npm ci --no-audit --no-fund
```

После успешной установки:

```powershell
npm test
npm run typecheck
npm run build
```

Сборку и проверку типов запускайте после остановки dev-сервера: Next.js
пересоздаёт `.next/types`, и одновременные процессы могут мешать проверке.

Для разработки с уже настроенным локальным Strapi:

```powershell
npm run dev -- --hostname 127.0.0.1
```

Для проверки готовой сборки:

```powershell
npm run start -- --hostname 127.0.0.1
```

Сайт доступен на http://127.0.0.1:3000. Остановка — Ctrl+C.
Файл `.env` должен содержать адреса вашего окружения; секреты не выводите в терминал и не добавляйте в Git.
`STRAPI_API_URL` — адрес CMS для сервера, `NEXT_PUBLIC_STRAPI_URL` — публичный адрес CMS и изображений.
Публичный адрес включается в сборку; после его изменения нужна новая сборка.

## Карточка товара

Новые ссылки используют Strapi `documentId`. Прежние числовые ссылки
ищут опубликованную запись по `id` и перенаправляют на адрес с `documentId`.
Карточка получает данные на сервере без API-токена, явно запрашивая image,
categories и device. Описание Strapi Blocks выводится как безопасный текст.
Отсутствующий товар, сбой CMS и отсутствие изображения имеют отдельные состояния.

Покупка и скачивание на карточке пока обозначены как недоступные.
Остальные незавершённые сценарии остаются отдельными этапами разработки.

В каталоге скачивание и покупка также заблокированы с пояснением; добавление
настоящих товаров в корзину сохранено. В корзине нет добавления демотовара,
оплата обозначена как недоступная. Прямой `/checkout/[id]` показывает сообщение
и возврат в корзину, не загружает заказ и не запускает заготовку оплаты.
Подписка не принимает email до запуска функции, история заказов явно обозначена
как будущая возможность. Социальные каналы без заполненного адреса не выводятся.

## Каталог и навигация

### Оформление

Экспериментальная палитра: бирюзовый градиент от тёмного к светло-голубому,
раздельные полупрозрачные плашки меню и коралловый акцент действия.
Onest 400 используется для текста, Onest 500 — для меню, Cormorant Garamond 400 —
для крупных заголовков. Файлы шрифтов и лицензии OFL находятся в `src/fonts`;
внешних запросов к Google Fonts при работе сайта нет.
Вход и блоки кабинета используют общий `FormField` с подписью и подсветкой
фокуса; оформление поля задаётся стилями его формы. Профиль и смена пароля подключены к серверным обработчикам;
подписка пока остаётся заглушкой. Анимации учитывают `prefers-reduced-motion`.

Авторизация использует общий стеклянный шаблон `AuthSurface`: `AuthScreen`
задаёт затуманенный фон, `AuthPanel` — градиентную панель с заголовком,
`AuthStack` — последовательное раскрытие полей и действий, `AuthNotice` —
уведомления и ошибки. Шаблон применяется к выбору сервиса, входу по email,
регистрации, подтверждению почты, восстановлению и созданию пароля,
продолжению OAuth-входа. Вход и регистрация используют один `EmailAuthForm`.
Стили `auth-*` изолированы от кабинета: полупрозрачный градиент сайта, Onest 500 для кнопок,
Cormorant Garamond 400 для заголовка и бирюзовую подсветку hover/focus.
Сначала виден заголовок в компактной панели, затем строки раскрываются
по очереди и увеличивают её высоту; итоговая ширина кнопок — до 260 px.
При reduced motion строки сразу видимы. В новых формах используйте эти
компоненты и классы `auth-button`, `auth-link`, `auth-copy`; полям остаётся
общий `FormField`. Дочерним элементам `AuthStack` задавайте постоянные ключи,
чтобы появление ошибки не сбрасывало фокус и введённые значения.
Новых UI-зависимостей нет.

### Поведение

Главная, страницы категорий и устройств используют единый каталог.
Карточки начинаются сразу под шапкой: отдельной панели фильтров и заголовка над сеткой нет.
«Категории» сразу открывают раздел. Кнопка «Фильтр» открывает компактный
выпадающий список с округлыми раскрывающимися полями категорий, устройств
и сортировки. Поиск по названию доступен сразу; выбранные условия подсвечиваются.
Изменения не меняют выдачу до нажатия «Применить».
Порядок по умолчанию сохранён из CMS.
Поиск по названию (`q`), категория (`category`), устройство (`device`),
сортировка (`sort`) и номер страницы (`page`) хранятся в URL.
Размер страницы — 12 обоев, общее количество берётся из Strapi `meta.pagination`.
Изменение условий через форму начинает выдачу с первой страницы.
Сброс фильтра и «Назад» в каталоге возвращают исходный раздел из пути URL.
Выбранная во вкладке категория может переопределять этот раздел через query,
включая пустую категорию (все обои), но исходная точка сброса сохраняется.
Карточка товара получает безопасный адрес возврата в `from`: возвращаются
условия, сортировка и номер страницы. Положение прокрутки сохраняется в пределах
вкладки на 30 минут; при недоступности storage остаётся обычный возврат по URL.
Товар без адреса возврата ведёт в общий каталог. Внешние адреса возврата запрещены.

`/category` и `/device` показывают опубликованные разделы Strapi.
Несуществующий раздел возвращает страницу «Страница не найдена».
На телефоне «Категории», «Фильтр» и «Назад» находятся в мобильном меню.
Фильтр раскрывается стрелкой внутри бургер-меню, как категории.
Клик вне бургер-меню и Escape закрывают его. Вход открывается отдельной формой.
Доступность API авторизации этим изменением не меняется.

## Docker и VPS

Отдельное окружение проверки email-авторизации: `../docker/AUTH_LOCAL.md`.
Регистрация, подтверждение и вход обращаются к Strapi через сервер Next.js.
Сессия хранится в HttpOnly-cookie; клиент получает пользователя через `/api/me`.
При регистрации по email подтверждение одноразовое, после него требуется вход.
Восстановление пароля доступно через «Забыли пароль?»; ссылка действует один час,
одноразовая. В кабинете сохраняются личные поля и меняется пароль с проверкой
текущего. Подтверждённый email не меняется через форму профиля. Ошибки и успех показываются внутри форм.
SMTP и шаблоны production настраиваются по `../backend/AUTH_SETTINGS.md`;
Google/Яндекс/Telegram: серверный OAuth bridge, локальная проверка и порядок
входа описаны в `../backend/OAUTH_SETTINGS.md`. Новый OAuth-пользователь сразу
попадает в кабинет без обязательной почты. Блок пароля показывает сервисы входа;
почту и первый пароль можно добавить позднее по одноразовой ссылке.

Реальный вход через провайдеров
нужно проверить после HTTPS-развёртывания. Подписка на рассылку ещё требует доработки.

Локальное окружение и сохранение данных: `../docker/LOCAL.md`.
Production: `../VPS_DEPLOYMENT_THEMESPHONE.md`, `../deploy/CICD.md` и `../deploy/PUBLIC.md`.
Команды Windows выше не являются командами для VPS. Перед изменением Strapi,
Compose или общего Caddy сначала прочитайте инфраструктурные инструкции.
